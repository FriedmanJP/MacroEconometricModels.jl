- **MIT / BSD-2 / BSD-3 / ISC / Apache-2.0 / Zlib / Public Domain**: `DataFrames`, `Distributions`, `ForwardDiff`, `JLD2`, `MadNLP` (`0.8.x`), `NonlinearSolve`, `Optim`, `PrecompileTools`, `PrettyTables`, `ScopedValues`, `SpecialFunctions`, `StatsAPI`, `Tables`, `OpenBLAS_jll`, `OpenSpecFun_jll`, etc.

- **LGPL-2.1-or-later / LGPL-3.0-or-later**: `LDLFactorizations`, `NLopt_jll` (`luksan` routines; MIT otherwise), `PureKLU` (LGPL-2.1+ / BSD-3).

## Optional Weak Dependencies (Not Bundled by Default)

The following solvers have GPL-incompatible licenses and are isolated in `[weakdeps]` so they are **never** installed or bundled by default:

- **`Ipopt`** (`ext/MacroEconometricModelsIpoptExt.jl`): `Ipopt_jll` (`EPL-2.0` without active Exhibit A Secondary Licenses) and `MUMPS_seq_jll` (`CeCILL-C`). Private end users may optionally opt in locally (`using Pkg; Pkg.add("Ipopt"); import Ipopt`, permitted under GPLv3 § 2) to use `solver=:ipopt`. The built-in GPL-compatible `solver=:madnlp` provides full interior-point NLP parity without Ipopt.
- **`PATHSolver`** (`ext/MacroEconometricModelsPATHExt.jl`): Proprietary PATH mixed-complementarity solver binary. Private end users may optionally load `import PATHSolver` locally to use `solver=:path`.

## Requirements for Downstream GPL-3.0-only Redistributors (e.g., `PackageCompiler`)

`NonlinearSolve` (via `LinearSolve`) and `FFTW` carry optional references to Intel's proprietary `MKL_jll` / `oneTBB_jll` / `IntelOpenMP_jll` (Intel Simplified Software License, ISSL — incompatible with GPL-3.0).

`MacroEconometricModels.jl` never invokes `MKLLUFactorization` or `FFTW.set_provider!("mkl")`:
- `compute_steady_state` explicitly passes a GPL-compatible dense linear solver (`LinearSolve.QRFactorization(LinearAlgebra.ColumnNorm())` via OpenBLAS) to `NonlinearSolve.TrustRegion`.
- `perfect_foresight` explicitly passes `linsolve=\` (block-Thomas / SuiteSparse UMFPACK).
- `FFTW` defaults to `provider = "fftw"` (`FFTW_jll`, GPL-2.0-or-later).

However, `LinearSolve.jl` checks the `LoadMKL_JLL` preference at package load time on x86_64 CPUs (defaulting to `true` on non-EPYC Intel x86_64 CPUs). **Downstream GPL-3.0-only redistributors building standalone applications or sysimages MUST list `LinearSolve` in their application's `Project.toml` (`[deps]` or `[extras]`, required for Julia's `Preferences.jl` to load `[LinearSolve]`) and pin the following preferences in `LocalPreferences.toml` before precompiling/bundling** (and exclude `MKL_jll`, `oneTBB_jll`, and `IntelOpenMP_jll` from redistributed binaries):

```toml
[LinearSolve]
LoadMKL_JLL = false

[FFTW]
provider = "fftw"
```
